AmdQuant is a web application for complex optimization problems, powered by AMD GPUs. It turns thousands of possible choices into a concrete plan, and lets users compare computation time and solution quality side by side.

The website includes eighteen examples across five categories. Each example explains the decision being made. Users can also enter their own supported data through the instructions and templates in the interface.

Let's start with Radio Channels, Problem One. Imagine two thousand and forty-eight radio transmitters, with only two channels available. Some pairs cause more interference than others when they share a channel. We need to assign a channel to every transmitter while keeping total interference as low as possible.

This example contains more than two million pairs of transmitters. It uses synthetic data and a fixed seed, so both engines receive exactly the same problem and we can reproduce the input.

I select Problem One and press Run. The two cards compare classical simulated annealing on the CPU with Simulated Bifurcation on an AMD GPU. Each card displays its result as soon as that engine finishes. We can inspect one solution while the other engine is still working.

In the recorded run shown here, the GPU completed three measured calls in about five hundred and ninety-eight milliseconds. The configured CPU baseline took about seven point three four seconds. The application reports a twelve point two seven times speedup in measured engine time.

The GPU also produced a slightly lower interference cost: five million, six hundred and fifty-nine thousand, six hundred and forty-two, compared with five million, six hundred and sixty thousand, nine hundred and sixty-seven for the CPU. Lower is better. We check quality alongside speed, and neither result is claimed to be the global optimum.

These timings measure the engines' work, rather than the browser's total waiting time or the network round trip. They compare the specific settings displayed on screen. Results can vary with the problem, the hardware and the run.

The other tabs address different decisions. Balance Tasks distributes work between two teams while accounting for workload and competition for shared resources. Select Projects weighs benefits, overlap costs and collaboration gains. Assign Jobs places computing work into two resource pools. Advanced QUBO lets technical users define their own binary optimization objective.

The larger generated examples contain up to four thousand and ninety-six decisions. Each category also offers a smaller own-data template with clear instructions. I open My Problem, load a template, edit the values and check the data. Unsupported requests or invalid inputs produce an explanation before execution.

The output is more than a score. Users can download the complete assignment and measurement record. Radio problems also provide a channel plan as a CSV file. The exported records include the problem specification, hardware, parameters, timings and solution checks.

The GPU engine uses the open-source Simulated Bifurcation package with PyTorch and AMD ROCm. This is quantum-inspired optimization running on conventional AMD hardware. The application verifies GPU availability and does not silently move that engine to the CPU.

This is an experimental service. If the GPU notebook is offline, Connecting appears with a spinning indicator and Run stays disabled. Email alerts ask the administrator to reactivate the notebook. Once the worker reconnects, Run becomes available again.

AmdQuant brings these optimization methods into an accessible interface: define a supported decision problem, compare two engines, inspect the results and export a usable plan. The goal is practical decisions supported by measurable performance and evidence users can inspect.
